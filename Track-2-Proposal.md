# UnvibeCode GitHub Pull Request Assistant

## Challenge
UnvibeCode Engineering Challenge 2026 – Cohort 3

## Track
Track 2 – Developer Adoption and Repeat Usage

## My Idea

I propose integrating UnvibeCode with GitHub Pull Requests. Whenever a developer opens or updates a pull request, UnvibeCode could automatically generate a code-impact report.

## Why this can improve adoption

1. **Regular usage:** Developers create pull requests frequently, giving them a reason to use UnvibeCode repeatedly.
2. **Better code understanding:** Reports can highlight affected files, connected business workflows and potential risks.
3. **Product visibility:** Branded comments on GitHub pull requests can introduce UnvibeCode to more developers.

## Implementation Plan

1. Build a GitHub Action that triggers UnvibeCode analysis when a pull request is opened or updated.
2. Publish a concise, branded report as a pull request comment, showing affected workflows and files.
3. Measure repeat usage through analysis reruns and returning repositories.

## Expected Impact

This integration could make UnvibeCode part of a developer's regular code-review workflow rather than a tool used only occasionally.

**Note:** This document describes a proposed feature, not an implemented integration.
